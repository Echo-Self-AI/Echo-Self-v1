# EchoSelf Cross-Language Architecture & AI Integration Guide

## 1. System Overview

EchoSelf decouples **high-concurrency job orchestration** (managed in Go) from **native machine learning inference** (implemented in Python with PyTorch primitives).

```text
┌────────────────────────────────────────────────────────────────────────┐
│                          Go Backend Ecosystem                          │
│                                                                        │
│   HTTP API Server ──► PostgreSQL Queue / Jobs ──► Asynchronous Workers │
│                                                         │              │
│                                                         ▼              │
│                                              processor.HTTPProcessor   │
└─────────────────────────────────────────────────────────┼──────────────┘
                                                          │
                                     HTTP POST /process   │ HTTP GET /health
                                     JSON Protocol        │
                                                          ▼
┌────────────────────────────────────────────────────────────────────────┐
│                         Python AI Microservice                         │
│                                                                        │
│                       ThreadedEchoSelfServer                           │
│                                 │                                      │
│                                 ▼                                      │
│                        EchoSelfAIService                               │
│        ┌───────────────┬────────────────┬───────────────┐              │

│   Transformer       Voice AI         Visual AI       Prompt-to-Video   │
│  Language Model    Synthesizer    Avatar Generator      Generator      │

```

## 2. Processor Contract Specification

The Go backend defines the `processor.Processor` interface in `backend/internal/processor/processor.go`:

```go
type Processor interface {
    Process(ctx context.Context, req ProcessRequest) (*ProcessResult, error)
    SupportedJobTypes() []string
}
```

### Request Payload (`ProcessRequest`)

| Field | Type | Description |
|---|---|---|
| `job_id` | `uuid.UUID` | Unique job identifier generated by Go queue. |
| `job_type` | `string` | Modality operation identifier (e.g. `llm_generate`, `avatar_generate`). |
| `user_id` | `uuid.UUID` | Authorized account requesting the operation. |
| `media_id` | `*uuid.UUID` | Optional source input media asset identifier. |
| `payload` | `map[string]any` | Parameter dictionary specific to the job type. |

### Result Payload (`ProcessResult`)

| Field | Type | Description |
|---|---|---|
| `output` | `map[string]any` | Synthesized assets, text completions, base64 media, and metadata. |
| `metadata` | `map[string]any` | Device identifier, latency in milliseconds, token counts. |

## 3. Error Classification & Fault Tolerance

The Go `HTTPProcessor` maps Python HTTP responses directly to backend error classes:

| HTTP Status | Python Condition | Go Sentinel Error | Worker Action |
|---|---|---|---|
| `200 OK` | Job completed successfully | `nil` | `MarkSucceeded` with output payload. |
| `400 Bad Request` | Missing parameters or invalid JSON | `ErrInvalidRequest` | `MarkFailed` (permanent). |
| `422 Unprocessable` | Security gate or consent violation | `ErrPermanentFailure` | `MarkFailed` with error message. |
| `500 Server Error` | OOM or internal computation fault | `ErrTransientFailure` | `ScheduleRetry` with exponential backoff. |
| `503 Unavailable` | Microservice overloaded or starting | `ErrTransientFailure` | `ScheduleRetry` with exponential backoff. |
| Network Timeout | Host unreachable or dropped connection | `ErrTransientFailure` | `ScheduleRetry` with jitter. |
| Context Canceled | Lease expired or user cancelled | `context.Canceled` | `AcknowledgeCancellation`. |

## 4. End-to-End Verification

### Running the Go E2E Bridge Test
The integration test spins up the live Python AI service and executes cross-language requests:
```bash
cd backend
go test -v -run TestE2E_GoToPythonAIService ./internal/processor
```

### Running the Python Bridge Test
Verifies that Python receives and serializes Go-typed requests:
```bash
cd ai
uv run pytest tests/test_go_bridge.py
```

## 5. Deployment & Local Development

To run the complete system locally:

1. **Start the Python AI Service**:
   ```bash
   cd ai
   uv run python -m echoself_ai.service.server --host 127.0.0.1 --port 8000
   ```

2. **Configure Go Worker Environment**:
   ```bash
   AI_SERVICE_URL=http://127.0.0.1:8000
   ```

3. **Start the Go Worker**:
   ```bash
   cd backend
   go run cmd/worker/main.go
   ```
